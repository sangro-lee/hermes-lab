# 용어집 — 쉽게 설명하기

- **Agent(에이전트)**: 목표를 받아 도구를 사용하고 여러 단계를 수행하는 AI 프로그램.
- **Orchestrator(오케스트레이터)**: 작업을 어떤 순서로 누구에게 맡길지 조율하는 구성 요소.
- **Hermes**: 이 프로젝트에서 연구 상태를 유지하고 여러 도구/작업자를 조율하도록 구성할 상위 에이전트. 실제 기능은 설치 버전과 연결 방식에 따라 다릅니다.
- **Claude Code / Codex**: 저장소를 읽고 코드를 작성·수정·테스트하는 데 활용할 코딩 에이전트. Hermes와의 연결은 CLI·MCP·권한 설정을 확인해 구성해야 합니다.
- **HPC**: High-Performance Computing. 여러 CPU/GPU 노드와 스케줄러를 이용해 계산하는 환경.
- **GPU 노드**: GPU 계산을 수행할 수 있는 서버. 클러스터 규칙에 따라 작업을 제출합니다.
- **Slurm**: HPC 작업 스케줄러. `sbatch`는 배치 작업 제출, `squeue`는 대기/실행 작업 확인, `scancel`은 작업 취소에 쓰입니다.
- **MCP**: Model Context Protocol. AI 에이전트가 파일·검색·데이터베이스·실험 도구 같은 외부 기능을 정해진 인터페이스로 호출하도록 돕는 프로토콜. 에이전트와 도구 사이의 공통 연결 규격이라고 생각하면 됩니다.
- **A2A**: Agent-to-Agent. 서로 다른 에이전트가 작업이나 상태를 주고받도록 돕는 에이전트 간 통신 방식.
- **AG-UI**: 에이전트의 진행 상태·승인 요청·결과를 사용자 인터페이스에 표시하는 데 초점을 둔 프로토콜/패턴.
- **ACP**: 문맥에 따라 뜻이 달라질 수 있는 약어입니다. 도입할 때는 해당 프로젝트의 공식 문서를 확인하고 필수 구성 요소로 가정하지 않습니다.
- **Cron**: Linux에서 “매일 오전 9시”처럼 정해진 시간에 명령을 실행하는 스케줄러. cron 자체가 AI는 아닙니다.
- **systemd timer**: Linux의 systemd를 이용해 예약 작업을 실행하는 방식. 서비스와 로그 관리에 편리한 cron의 대안입니다.
- **MCP server**: 에이전트가 호출할 도구를 제공하는 서버 프로그램. 예를 들어 안전한 `researchctl status` 기능을 도구로 노출할 수 있습니다.
- **JSON Schema**: JSON 문서의 필수 필드와 자료형 등을 정의하는 규칙. 실험 명세의 `seed`가 정수인지 검증하는 데 씁니다.
- **Git**: 코드와 문서의 변경 이력을 기록하는 버전 관리 시스템.
- **DVC**: Data Version Control. Git으로 다루기 어려운 대용량 데이터·모델 파일의 버전과 파이프라인을 추적하는 도구.
- **Commit**: Git에서 특정 시점의 변경 내용을 기록한 버전 식별자.
- **Seed(시드)**: 난수 생성의 시작값. 재현성에 도움을 주지만 모든 비결정성을 없애지는 않습니다.
- **Baseline(베이스라인)**: 새 방법과 비교할 기준 모델 또는 기준 실험.
- **Metric(지표)**: MAE, RMSE, 성공률, 유효 분자 비율처럼 실험 결과를 수치로 평가하는 기준.
- **Research State**: 현재 연구 목표·진행 상황·핵심 결과·다음 질문을 정리한 파일.
- **Skill(스킬)**: 반복 작업을 일정한 절차로 수행하기 위한 지침/워크플로 파일. 만들었다고 자동으로 검증된 것은 아닙니다.
- **OpenTelemetry**: 여러 서비스에서 trace(요청 흐름), metric(수치), log(기록)를 모으기 위한 관측성 표준.
- **Observability(관측성)**: 로그·지표·추적 정보로 시스템 내부 동작을 이해할 수 있는 정도.
- **Workflow(워크플로)**: 실험 준비→검증→실행→분석→기록처럼 연결된 단계들의 흐름.
- **Prefect / Temporal**: 실패 재시도, 단계 상태 저장, 장시간 실행을 관리하는 도구. 초기 버전에서는 과할 수 있습니다.
- **Human-in-the-loop**: 중요한 단계에서 사람이 확인하거나 승인하는 설계.
- **Least privilege(최소 권한)**: 작업에 꼭 필요한 최소한의 권한만 부여하는 보안 원칙.
- **Worktree**: Git에서 서로 다른 브랜치를 별도 디렉터리로 체크아웃하는 기능. 에이전트 간 파일 충돌을 줄이는 데 쓸 수 있습니다.
