# 구축 계획 — 6주 단계별 진행

## 목표
연구자가 방향과 중요한 결정을 통제하면서, AI가 조사·실험 제안·제한된 실행·결과 분석·연구 기록 업데이트를 반복하도록 구성합니다.

## 0단계 — 안전한 시작 환경 (1주차)
- [ ] Hermes용 별도 Linux 계정 또는 격리된 실행 환경 검토
- [ ] 프로젝트 전용 작업 디렉터리 생성
- [ ] 로그인 노드와 계산 노드 사용 규칙 확인
- [ ] Slurm partition, GPU 종류, 시간 제한, 메모리 제한 파악
- [ ] 비밀키와 API 키는 저장소 밖에 보관
- [ ] 이 저장소를 Git으로 관리

완료 기준: 에이전트가 읽고 쓸 수 있는 경로, 실행 가능한 명령, 금지된 작업이 문서화되어 있음.

## 1단계 — 연구 상태와 실험 명세 (1–2주차)
- [ ] `config/project.yaml` 수정
- [ ] `research/RESEARCH_STATE.md`에 현재 연구 상황 기록
- [ ] 가설·결과·미해결 질문을 별도 파일에 기록
- [ ] 실험 명세를 템플릿에서 복사해 작성
- [ ] JSON Schema 검증 스크립트 실행
- [ ] Git commit, 데이터 버전, seed, metric, 성공 기준 기록

완료 기준: 대화창이 바뀌어도 프로젝트 파일만 보고 현재 상태와 다음 실험을 이해할 수 있음.

## 2단계 — 코딩 에이전트 연결 (2주차)
- [ ] Claude Code와 Codex 설치·인증·권한 방식 확인
- [ ] 작은 저장소에서 읽기 전용 코드 분석부터 시험
- [ ] 작업 요청에 파일 경로, 목표, 금지 사항, 테스트 기준 명시
- [ ] 동시 수정 충돌을 줄이기 위해 별도 작업 디렉터리 또는 Git worktree 검토
- [ ] 코드 변경은 자동 병합하지 않고 사람이 검토

## 3단계 — 제한된 실험 실행 (3주차)
- [ ] `deployment/slurm/gpu_job_template.sbatch`를 클러스터에 맞게 수정
- [ ] `researchctl`에 상태 확인 기능부터 구현
- [ ] CPU/짧은 smoke test부터 실행
- [ ] GPU 작업은 명세·자원·예상 시간을 사람이 확인한 뒤 제출
- [ ] 로그·종료 코드·결과 파일 위치 기록
- [ ] 실행 중인 작업 확인/중단 절차를 별도로 테스트

## 4단계 — 분석과 연구 기록 갱신 (4주차)
- [ ] metric 계산 방법을 코드로 고정
- [ ] baseline과 비교
- [ ] 결과 표·그림을 재생성 가능하게 저장
- [ ] 에이전트는 `FINDINGS.md`와 `RESEARCH_STATE.md` 수정안을 제안
- [ ] 연구자가 해석과 기록 변경을 승인

## 5단계 — 반복 작업 자동화 (5주차)
- [ ] 정기 상태 점검 스크립트부터 자동화
- [ ] 이후 cron 또는 systemd timer로 연구 요약 생성
- [ ] 자동 실행은 읽기/요약부터 시작
- [ ] GPU 실행은 승인 정책 유지
- [ ] 로그와 실패 알림 경로 확인

## 6단계 — 관측성과 확장 (6주차 이후)
- [ ] 여러 구성 요소가 연결된 뒤 OpenTelemetry 검토
- [ ] 재시도와 장기 작업이 복잡해지면 Prefect/Temporal 검토
- [ ] 에이전트 간 상호작용이 필요할 때 A2A 검토
- [ ] 대용량 데이터/체크포인트 추적이 필요하면 DVC 검토
- [ ] 몇 주간의 실험 기록을 바탕으로 자율성을 점진적으로 확대

## 권장 초기 승인 정책
| 작업 | 초기 정책 |
|---|---|
| 프로젝트 문서 읽기·요약 | 자동 허용 |
| 코드 검색·정적 분석 | 자동 허용 |
| 단위 테스트 / 짧은 CPU 테스트 | 제한된 경로에서 허용 |
| 파일 수정 | 별도 브랜치에서 허용, diff 검토 필수 |
| GPU 작업 | 처음에는 매번 승인 |
| 장시간·대규모 GPU 작업 | 명시적 승인 필수 |
| 연구 상태/결과 파일 변경 | 변경안 검토 후 반영 |
| 새 스킬의 공용 승격 | 반복 시험 후 사람 승인 |
| `sudo`, 시스템 설정 변경 | 금지 |
| 데이터 삭제·작업 취소 | 명시적 확인 필수 |
| API 키/토큰 출력 또는 커밋 | 금지 |

## 파일럿 연구
현재 진행 중인 VQC 기반 diffusion denoiser 연구를 파일럿으로 삼을 수 있습니다. 익숙한 연구이므로 AI의 가설·코드 변경·결과 해석을 연구자가 검증하기 쉽습니다. 첫 목표는 완전 자율 연구가 아니라 **재현 가능한 한 번의 실험 사이클**을 완성하는 것입니다.
